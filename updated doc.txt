# 1. THE CORRECTED BUSINESS MODEL

KNIGHT is the central control and management platform.

Customer stores are independent Django applications.

Example:

```text
KNIGHT
   |
   +-------------------+
   |                   |
   v                   v
Cafe 1              Cafe 2
Django              Django
cafe1.ir            cafe2.ir
```

Every store has:

* its own domain
* its own Django application
* its own database
* its own configuration
* its own deployment
* potentially its own server

KNIGHT is NOT the business backend of these stores.

---

# 2. CRITICAL CORRECTION: FEATURES

The previous documentation incorrectly treated Features primarily as:

```text
Feature = entitlement / flag
```

That is incomplete and must be corrected.

The actual model is:

```text
Feature = versioned, deployable Django functionality
```

A Feature is developed **once**.

It is NOT manually reimplemented for every customer.

For example:

```text
Feature:
Advanced Analytics
Version:
1.4.0
```

is developed once as a reusable Django package/module.

When Customer A purchases it, KNIGHT automatically installs/configures/enables the existing Feature in Customer A's Django application.

When Customer B purchases the same Feature, KNIGHT uses the same Feature package/version and deploys it to Customer B.

There must be NO manual feature development per customer.

# 12. FEATURE ENTITLEMENT VS FEATURE INSTALLATION

This distinction is mandatory.

These are two different concepts:

```text
ENTITLEMENT
=
Customer is allowed to use Feature X
```

and:

```text
INSTALLATION
=
Feature X has actually been deployed to the customer's Django application
```

A customer may have:

```text
Entitlement = true
Installation = failed
```

or:

```text
Entitlement = true
Installation = pending
```

or:

```text
Entitlement = true
Installation = successful
```

The domain model and documentation must represent these states appropriately.

Do NOT collapse them into a single boolean.

# 24. SECURITY REQUIREMENTS FOR FEATURE DELIVERY

Feature packages are executable software.

Therefore Feature delivery is a high-risk operation.

The architecture must address:

* package authenticity
* package integrity
* secure transport
* authorization
* version validation
* compatibility validation
* credential security
* rollback/failure handling
* audit logging

Do not design Feature installation as downloading arbitrary code from an unauthenticated URL.

# 31. MICROservice DECISION REMAINS UNCHANGED

Do not convert Feature Packages into microservices.

A Feature Package is NOT automatically a microservice.

For example:

```text
Analytics Feature
```

may simply be:

```text
Django Package
```

installed inside the customer's Django application.

Do NOT deploy:

```text
Analytics Service
AI Service
SMS Service
```

as separate network services unless there is a genuine architectural requirement.

The goal is:

```text
ONE STORE DJANGO APPLICATION
+
MULTIPLE INSTALLABLE FEATURES
```

not:

```text
ONE STORE
+
20 MICROSERVICES
```

The architecture should now converge toward:

```text
                         ┌─────────────────────────┐
                         │        KNIGHT           │
                         │                         │
                         │ ASP.NET Core            │
                         │ Feature Registry        │
                         │ Subscription            │
                         │ Entitlements            │
                         │ Deployment Engine       │
                         │ Monitoring              │
                         │ Error Management        │
                         │ Audit                   │
                         └────────────┬────────────┘
                                      │
                              Feature Package
                                      │
                     ┌────────────────┼────────────────┐
                     │                │                │
                     ▼                ▼                ▼
                  Store A          Store B          Store C
                  Django           Django           Django
                     │                │                │
                Feature A       Feature A+B       Feature C
                Feature C       Feature C         Feature D
                     │                │                │
                  Server A         Server B       Dedicated Server
```

The most important property is:

```text
A Feature is implemented ONCE.

KNIGHT manages its versions.

Customers purchase entitlements.

KNIGHT automatically delivers and installs the Feature into the appropriate Django Store.

The developer does NOT manually implement the Feature again for each customer.
```
